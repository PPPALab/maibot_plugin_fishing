# 钓鱼小游戏

版本：**1.0.2** · 仓库：[PPPALab/maibot_plugin_fishing](https://github.com/PPPALab/maibot_plugin_fishing)

插件 ID：`github.PPPALab.maibot_plugin_fishing`。

为 MaiBot 提供钓鱼小游戏、装备、交易市场、及管理后台。基于
[AstrBot Fishing](https://github.com/sakuradairong/astrbot_plugin_fishing) 原生移植，
无需安装 AstrBot 或 NoneBot。

## 功能

- 钓鱼、签到、区域切换、鱼类图鉴、鱼塘和水族箱。
- 鱼竿、鱼饵、饰品、道具、精炼及成就称号。
- 商店、玩家市场、转账、红包及大宗商品交易所。
- 抽卡、擦弹、命运之轮、骰宝、偷鱼和电鱼。
- MaiBot 中文分组配置表单；独立 Web 后台管理鱼类、卡池和商品。
- 独立 SQLite 数据目录，支持备份、恢复及旧配置自动补版本。

## 兼容性

- **MaiBot 1.3.19 / maibot-plugin-sdk 2.20.0**。
- QQ 收发使用 MaiBot 现有适配器。其他宿主和 SDK 版本尚未验证。

## 安装

1. 下载本仓库源码，解压到 MaiBot 的插件源码目录，例如
   `plugins/maibot_plugin_fishing/`，确保该目录直接包含 `_manifest.json` 和 `plugin.py`。
2. 重启 MaiBot。宿主会按 manifest 自动安装缺少的依赖；禁用自动安装的部署请在
   Runner 的 Python 环境安装 `requirements.txt`。
3. 在 MaiBot 插件设置页填写**管理员 QQ 账号**，保存配置。
4. 在测试群发送 `注册`、`签到`、`钓鱼` 和 `钓鱼帮助`。

不要覆盖旧 `maibot-plugin-fishing` 插件，也不要复制旧插件的配置或数据库到本插件。
升级时保留本插件的 `config.toml` 和 SDK 数据目录，只更新源码后重启。

## 常用命令

命令可省略开头的 `/`。参数中的数字和账号需替换为实际值。

```text
注册                 签到                 钓鱼
钓鱼帮助             状态                 背包
鱼塘                 水族箱               鱼类图鉴
商店                 市场                 交易所
抽卡                 查看卡池 3           骰宝帮助
```

更多玩法命令请在聊天中发送 `钓鱼帮助` 查看；命令注册、别名和权限定义见 [commands.json](commands.json)。

## 配置与管理后台

日常参数可在 **MaiBot → 插件设置 → 本插件** 编辑，支持中文分组、数字校验、开关和选择框。
管理员仅以配置中的 QQ 账号列表为准，不自动信任群头衔。

请区分两个页面：

- **MaiBot 插件设置页**：设置管理员 QQ、玩法参数、后台开关及密码，使用 MaiBot 自己的登录方式。
- **本插件的钓鱼管理后台**：管理鱼类、卡池奖品和商店商品，默认关闭，单独监听端口，使用本插件设置的密码登录。

只玩游戏、使用 MaiBot 设置页时，**无需启用钓鱼后台，也无需开放 7777**。

### 局域网访问钓鱼后台

以下以**服务器 IP 为 `192.168.1.10`** 举例，请换成运行 MaiBot 的服务器实际局域网 IP，

`config.toml`，修改其中的 `[webui]` 节，不要重复添加同名节：

```toml
[webui]
enabled = true
listen_host = "0.0.0.0"
port = 7777
allowed_hosts = ["localhost", "127.0.0.1", "[::1]", "192.168.1.10"]
secret_key = "请替换为你自己的独立密码"
```

- `secret_key` 就是**登录密码**，支持中文，不能留空或全空白。
- `listen_host = "0.0.0.0"` 表示容器内接受各网卡连接
- `allowed_hosts` 填浏览器地址栏使用的**服务器 IP 或精确局域网主机名**；不是允许访问的客户端 IP 列表。
  不带协议、端口、路径，不填通配符。若用另一个局域网主机名访问，也需将该主机名加入列表。
- 保存后确认插件加载正常；手动编辑配置文件后需重新加载插件。

## 数据、缓存与移除插件

### 数据放在哪里

本插件使用**独立 SQLite 数据库**。
宿主只分配目录；数据库的读写、事务、版本迁移由插件负责。

默认目录（相对于 MaiBot 根目录，实际以宿主分配路径为准）：

```text
plugins/<插件源码目录>/config.toml             配置，包括后台密码
data/plugins/github.PPPALab.maibot_plugin_fishing/
  astrbot-fishing.sqlite3                     玩家、金币、装备、库存及游戏状态
temp/plugins/github.PPPALab.maibot_plugin_fishing/
  tmp/                                       生成图片
  avatar_cache/                              头像缓存
  fish_icon_cache/                           鱼图缓存
```

### 从 1.0.0 升级

1.0.1 将插件 ID 从 `fishing.astrbot-native` 改为 `github.PPPALab.maibot_plugin_fishing`。
宿主会将其视为新的插件身份，不会自动迁移旧 ID 的数据。

1. 完全停止 MaiBot，备份插件 `config.toml` 和整个旧持久化目录。
2. 将 `data/plugins/fishing.astrbot-native/` 整个目录迁移至
   `data/plugins/github.PPPALab.maibot_plugin_fishing/`（实际以宿主分配路径为准），
   包括数据库及存在的 `-wal`、`-shm` 文件；如果目标目录已有数据，先备份并核对，不要直接覆盖或合并。
3. 更新插件源码并保留 `config.toml`；在宿主中重新扫描、启用新 ID，确认旧 ID 不再运行。
4. 启动后确认玩家进度和管理员配置。旧 ID 的临时缓存无需迁移，会自动重新生成。

### 缓存如何清理

清理由**插件自己的定时任务**执行，不是宿主的统一缓存服务：

- 生成图片 `tmp/` 和头像 `avatar_cache/`：按文件修改时间，超过24小时清理。
- 鱼图 `fish_icon_cache/`：超过7天清理。
- 上述三个目录内的常规文件合计超过100 MiB时，按修改时间优先删除较旧文件，直到不超过上限。
  这是定时检查的限制，不是实时磁盘配额；两次检查之间可能暂时超出。
- 插件加载后的首次后台检查会尝试清理，之后约每小时检查一次；插件停止、禁用或移除后不再定时清理。
- 更新前遗留在旧数据目录中的缓存不会主动删除。需要手动清理时，先停用插件、确认路径，
  只处理本插件的图片缓存目录，不要删除数据库及SQLite附属文件。

缓存被清理后会按需重新生成或下载，不会清空玩家进度。

### 停用、更新或移除会删除数据吗

**本插件没有自动清空数据功能，也不会在卸载回调中删除文件。** 该回调在停用、重载、
更新、关机时也可能执行；自动删除会误伤正常使用。

- **停用、重载、重启**：插件保留数据库和配置，关闭任务并释放资源。
- **更新源码**：应保留 `config.toml` 和整个持久化数据目录。数据迁移在加载时执行。
- **在 MaiBot 中移除插件**：当前参考宿主实现删除插件源码目录，因此其中的配置也可能丢失；
  独立的数据和缓存目录并不会由本插件自动删除。其他宿主版本或卸载选项可能不同，移除前务必备份。
- **永久清除所有信息**：先停用插件并备份，再移除插件，最后人工核对并删除**本插件专属**数据和缓存目录。
  不要删除整个 `data/plugins`、`temp/plugins` 或其他插件目录。另存的数据库备份、旧配置备份和下载文件也需自行管理。

### 备份与恢复

备份应同时保留 `config.toml` 和游戏数据。运行中的SQLite可能有 `-wal` / `-shm` 文件，
**不要只复制一个正在写入的 `.sqlite3` 文件**。推荐使用插件自带备份工具，或者完全停止插件后备份整个数据目录。

## 常见问题

- **签到成功但每日补给未配置？** 金币和高级货币已到账。上游默认每日补给池未填奖品，
  请管理员在钓鱼后台的卡池管理中配置；插件不会自动编造奖励。
- **升级提示缺少 `[plugin]`？** 当前版本会在宿主校验前备份并自动补齐旧配置的版本信息。
  若仍失败，检查源码目录写入权限和 TOML 格式，不要删除数据库。
